# 한 장 요약 — 무엇으로 만들었고, 왜 그렇게 골랐나

> 이 문서는 다른 문서로 안내하는 진입점이다. 규칙의 정본은 [DESIGN.md](../DESIGN.md)이고, 결정 하나하나의
> 근거는 [docs/adr/](./adr/)에 있다. 여기에는 전체 그림과, "왜" 그렇게 골랐는지에 대한 요점만 둔다.

## 전체 그림

```
┌──────────────── 한 벌의 정적 빌드 (Vite + React 18 + TypeScript) ────────────────┐
│ 편집(행 = textarea) · 병합(merge.ts, 순수 함수) · 검증(validate.ts) · 질의 언어   │
└──────┬───────────────────┬───────────────────┬──────────────────┬───────────────┘
       │ 브라우저 탭         │ 설치된 PWA          │ 데스크톱 앱        │ Android 앱
       │                   │ (오프라인 셸 캐시)   │ Tauri 2 셸        │ Tauri 2 셸
       │                   │                    │ + 폴더 백엔드      │
       │                   │                    │ + 로컬 파일 사본    │ + 로컬 파일 사본
       └─────────┬─────────┴──────────┬─────────┴──────────┬───────┘
                 ▼                    ▼                    ▼
        GitHub 저장소          동기화 서비스 폴더       내 서버 / URL
        (문서당 파일, 커밋       (outliner.json 하나,    (Cloudflare Worker,
         = 버전 백업)            iCloud·Dropbox 등)      레퍼런스 서버, Firebase)
```

원격은 모두 선택 사항이다. 원격을 켜지 않으면 각 기기에서 로컬로만 쓴다. 원격을 켜면 **병합은 언제나 기기에서**
일어나고, 원격은 바이트를 보관할 뿐이다.

## 선택과 그 이유

| 선택 | 이유 | 버린 대안 | 근거 |
|---|---|---|---|
| **병합을 클라이언트에** | GitHub·폴더·아무 서버가 모두 원격이 될 수 있고, 종단 간 암호화가 가능해진다 | 서버가 판정하는 동기화 | [ADR-0002](./adr/0002-client-side-merge.md) |
| **범용 CRDT 대신 필요한 셋만** (분수 정렬 키, 내용·위치 별도 스탬프, 묘비) | 아웃라인이 병합되는 데 필요한 것은 이 셋뿐이고, 범용 CRDT보다 구현 규모가 한 자릿수 작다 | Yjs·Automerge | [ADR-0003](./adr/0003-custom-merge-model.md) |
| **행마다 `<textarea>`, 서식은 마크다운 문자열** | 한글 IME가 브라우저의 기본 동작 그대로 작동한다. 내보내기를 해도 서식이 유지된다 | contenteditable WYSIWYG | [editing.md](./design/editing.md) |
| **런타임 의존성 = react, react-dom, 지연 로드 katex** | 번들이 작고 성능이 예측 가능하다. 가상화·하이라이트·질의 언어를 직접 구현한다 | 에디터 프레임워크 | [ADR-0004](./adr/0004-katex-lazy-load.md) |
| **단축키는 표 하나 + 프리셋 둘** | 마크다운 에디터 관례와 Dynalist 관례는 같은 키를 다르게 쓴다. 단축키를 표로 분리하면 둘 다 고를 수 있고, 그 표는 기기 사이에서 동기화된다 | 하드코딩 | [ADR-0006](./adr/0006-keymap-presets.md), [0008](./adr/0008-keymap-travels.md) |
| **네이티브 앱은 Tauri 2** | 한 프로젝트로 macOS·Windows·Linux·Android 앱을 만든다. 시스템 웹뷰를 사용하므로 설치 파일이 수 MB다. 디스크의 파일을 백그라운드에서 읽고 쓸 수 있다 | Electron(무겁고 Android 미지원), Capacitor(데스크톱 미지원), PWA만(폴더 백엔드 불가) | [ADR-0010](./adr/0010-native-shell.md) |
| **셸은 판정하지 않는다** | 브라우저와 앱이 같은 규칙으로 병합하고, 신뢰 경계가 하나로 남는다 | Rust 쪽에서 하는 병합·검증 | DESIGN.md 원칙 20 |
| **"파일 하나가 정본"은 동기화 서비스 폴더로** | 서버를 운영하지 않아도 되므로 무료이고, 파일을 사용자가 직접 보관한다. 사용자가 이미 쓰는 서비스를 그대로 쓴다 | 직접 만든 파일 전송 | [ADR-0011](./adr/0011-folder-backend.md) |
| **CAS 없는 원격은 루프가 보정하되, 남의 바이트는 지우지 않는다** | 동기화 서비스는 사전 확인 없이 파일을 바꾼다. 보정하지 않으면 유실된 쓰기가 복구되지 않고, 바이트를 지우는 방식으로 보정하면 데이터가 손실된다 | 편집이 있을 때만 푸시 | DESIGN.md 원칙 21 |
| **무료 서버는 Cloudflare Worker + Durable Object** | 결제 수단 없이 배포할 수 있고, 회수되지 않으며, 강한 일관성을 제공하므로 CAS가 성립한다 | 무료 VM(회수됨), KV(결과적 일관성), R2(결제 수단 필요) | [backend-capacity.md](./research/backend-capacity.md) |
| **소스 구조는 FSD light** | 새 코드를 둘 위치를 그 코드가 무엇을 아는지에 따라 정한다. import 방향은 스크립트가 강제한다 | 도메인 폴더만 두기, 정통 FSD, 패키지 분할 | [ADR-0013](./adr/0013-fsd-light.md) |
| **앱은 자기 파일에도 저장한다** | 웹뷰의 저장소 정책에 노트를 맡기지 않는다. 두 사본은 한 기기의 기록이므로 병합하지 않고 더 최신인 쪽을 쓴다 | IndexedDB만 | [native.md](./design/native.md) |
| **날짜는 텍스트 표기** | Dynalist에서 가져온 날짜가 변환 없이도 날짜로 표시된다. 스키마와 병합 규칙은 바뀌지 않는다 | 날짜 필드, 일정 기능 | [ADR-0012](./adr/0012-dates-as-text.md) |
| **빌드는 GitHub의 무료 러너** | 개발 기기에 Rust·Android SDK가 없어도 태그 하나로 네 플랫폼용 빌드가 만들어진다. 서명 키는 서드파티 스크립트가 없는 잡에서만 디코딩된다 | 로컬 빌드 | [native.md](./design/native.md) 「빌드」 |

## 어떻게 검증하나

| 층 | 무엇 |
|---|---|
| 유닛 (Vitest) | 정렬 키, 트리 연산, 병합, 검증, 질의 언어, 날짜, 폴더 백엔드와 푸시 판정 |
| e2e (Playwright, 실제 브라우저) | 편집·IME·드래그, 서식 키보드, 두 기기 동기화, 적대적 서버, 암호, 레퍼런스 서버 프로세스, 2,000줄 성능, 폰 에뮬레이션 |
| 구조 검사 (`npm run check:layers`) | 층·슬라이스 사이의 import 방향 ([ADR-0013](./adr/0013-fsd-light.md)) |
| `folder.rs` 단독 테스트 | 셸의 디스크 작업 전부 (허용 목록 포함) |
| 네이티브 스모크 | **실제 Linux 앱**(tauri-driver)과 **에뮬레이터의 Android APK**를 구동해 입력·IPC·파일·충돌 사본·창 인셋을 확인한다. macOS·Windows 앱은 실행해서 첫 저장이 로컬 사본에 기록되는지까지 확인한다 |
| 독립 리뷰 | 브랜치 전체를 행동 기준으로 검토해 데이터 손실 경로를 찾는다. 2026-09-29 리뷰에서 찾은 내용은 ADR-0011의 「리뷰 후기」에 기록되어 있다 |

자동 검증으로 확인하지 못하는 부분도 적어 둔다. macOS·Windows 앱은 실행까지만 확인하고 입력은 구동하지 않는다.
그리고 동기화 서비스가 실제로 만드는 충돌 사본의 이름은 실제 서비스에서만 확인할 수 있다(PLANS.md 10번).
