# 다이나리스트 격차 분석

> (원래는 루트의 `PARITY.md`였다. 2026-08-20에 문서 체계를 개편하면서 여기로 옮겨 왔다. 격차 분석·로드맵 이력과 스키마 변경 총계를 기록한 문서다.)

> "백본은 잡혔다. 그래서 **다이나리스트를 끊으려면** 무엇이 더 필요한가."
>
> 이 문서는 기능 목록을 비교한 표가 아니라, 다이나리스트를 매일 쓰는 사람의 **손에 익은 동작**을 기준으로
> 정리한 것이다. 아키텍처와 설계 근거는 [DESIGN.md](../DESIGN.md)가 정본이고, 이 문서는
> "무엇이 빠졌고, 이 코드베이스에서 그걸 넣으려면 어디를 건드리는가"만 다룬다.

## 한 줄 요약

**구조(아웃라인 편집·동기화·저장)는 이미 다이나리스트와 같은 급이거나 더 낫다.
빠진 것은 전부 "노트를 쓰는 일" 위에 얹힌 층이었다.**

그리고 방향은 다이나리스트를 그대로 베끼는 것이 아니라,
**편집은 마크다운 에디터처럼, 항해는 코드 에디터의 팔레트처럼** 만드는 것이다.
다이나리스트의 날짜·일정 계열 기능은 목표에서 **뺀다**(§5).

> **현황: P0·P1·P2가 전부 구현됐다** (§6). 예외는 하나뿐이다: Tauri 데스크톱은 **안 하기로** 했다.
> 예측대로 **병합 모델은 바뀌지 않았다**: 달라진 것은 새 병합 규칙 하나(`created`는 더 이른 쪽)와
> 스키마 v6(필드 추가뿐)이고, 동기화 페이로드는 그대로다.

## 2. 축별 상세

> 아래는 **구현 전에 쓴 분석**이고, 지시대로 그대로 둔다. 왜 그렇게 만들었는지는 여기에 적혀 있다.
> 무엇이 실제로 들어갔는지는 §6이, 모델이 어떻게 끝났는지는 §7이 정본이다.

### 2.1 아웃라인 조작 — 이미 동등하거나 낫다

되는 것은 무한 깊이, 접기, 확대(zoom)와 브레드크럼, Enter로 분리, Tab/Shift+Tab, Backspace로 병합,
⌘⇧↑↓로 이동, Esc로 항목을 선택한 뒤 일괄 조작, 메모, 체크박스, 인라인 마크다운, `#태그`, 드래그,
붙여넣기로 트리 삽입, 실행 취소다.

**빠진 것은 셋이다.** 크기는 작지만 매일 눈에 띄는 종류다.

| 빠진 것 | 다이나리스트 | 여기서 필요한 것 |
| --- | --- | --- |
| 체크리스트 토글 | 체크박스는 **부모를 체크리스트로 지정했을 때만** 그 자식들에 뜬다 | 지금은 `Row.tsx`가 모든 행에 체크박스를 그린다. 체크박스를 안 쓰는 사람에게는 이것이 전부 소음이다. 부모에 `checklist: boolean`을 둔다 |
| 번호 목록 | 부모를 번호 목록으로 바꾸면 자식에 1. 2. 3. 번호가 붙는다 | 부모에 `numbered: boolean`을 둔다. `Row`가 이미 `row.index`를 알고 있으므로 렌더만 바뀐다 |
| 색 라벨 | 6색으로 즉시 분류한다 | 노드에 `color: 0..6`을 둔다. CSS 변수 하나면 된다 |

셋 다 **노드의 필드 하나**이고, `edited` 스탬프를 기준으로 하는 LWW를 그대로 따른다. `merge.ts`도 `validate.ts`도
필드를 추가하는 것 이상으로는 바뀌지 않는다. 그리고 셋 다 §2.2의 자동 서식으로 **키보드에서 만들어져야** 한다.

### 2.2 글을 쓰는 손맛 — 지금 가장 크게 비어 있는 곳

**모델은 이미 마크다운 에디터인데, 키보드 조작은 거기에 미치지 못한다.**

지금 구조는 옳다. 포커스가 있으면 원문 textarea를, 없으면 렌더된 마크다운을 보여 준다. 이것은 Obsidian·Typora와
같은 모델이고, 한글 IME가 브라우저 기본 동작으로 작동하는 이유다. **이 구조는 바꾸지 않는다**
(편집 중에도 서식이 보이는 다이나리스트식 WYSIWYG를 구현하려면 contenteditable이 필요하고,
그러면 IME 조합이 깨진다. DESIGN.md가 그 대가를 치르고 얻은 것이다).

바꿔야 할 것은 그 위에 있는 키보드 조작이다. 증상 하나로 요약하면 이렇다:
**`heading` 필드는 모델에도, 내보내기에도, 붙여넣기 파서에도 있는데
(`tree.ts:593`), 라이브 편집에서 제목을 만들 방법이 아예 없다.**
제목은 지금 가져오기나 붙여넣기로만 존재할 수 있다. 이와 같은 계열의 구멍이 여러 개 있다.

#### (a) 서식 단축키 — 선택 영역 감싸기

| 키 | 결과 |
| --- | --- |
| ⌘B / ⌘I | `**굵게**` / `*기울임*` |
| ⌘E | `` `코드` `` |
| ⌘⇧X / ⌘⇧H | `~~취소선~~` / `==강조==` |
| ⌘K | `[선택](url)` (링크) |

규칙은 셋이다. 감싸기는 **토글**이어야 한다(이미 감싸져 있으면 벗긴다). 선택 영역이 없으면 마커만 넣고 캐럿을
가운데에 둔다. 그리고 **되돌리기 한 번에 원래대로** 돌아가야 한다.

구현 주의: `Editable`의 textarea는 포커스가 있는 동안 **비제어**다(DESIGN.md). 감싸기는 값과
캐럿을 동시에 건드리므로, 바깥에서 값을 덮어쓰는 기존 경로("마지막으로 내보낸 값과 다를 때만")와
어떻게 맞물리는지가 이 작업에서 유일하게 까다로운 지점이다.

#### (b) 자동 서식 — 타이핑이 곧 서식

아래 입력을 줄 맨 앞에서 치면 그 자리에서 서식으로 변환된다. 마크다운에 손이 익은 사람이 기대하는 바로 그 동작이다.

| 입력 | 결과 | 필요한 것 |
| --- | --- | --- |
| `# ` `## ` `### ` | 제목 1/2/3 | **지금 유일한 경로가 없다.** 필드는 이미 있다 |
| `- [ ] ` 또는 `[] ` | 체크박스 | `done`이 이미 있다 |
| `1. ` | 번호 목록 | §2.1의 `numbered` |
| `> ` | 인용 | 새 필드 또는 인라인 표기 |
| `` ``` `` | 코드 블록 | §2.2(d) |

`parseOutlineLine`이 이미 `- `, `[x] `, `#`를 읽는다. 즉 **파서는 있고 입력 경로만 없다.**
자동 변환 직후 Backspace를 한 번 누르면 원문으로 되돌아가야 한다(에디터 관용구).

#### (c) 자동 완성과 자동 쌍

- `[[` → **문서·항목 자동완성 팝업.** 지금은 `[[제목]]`을 끝까지 손으로 쳐야 하고,
  틀리면 조용히 새 문서가 생긴다(`App.tsx`의 `openDocByTitle`)
- `#` → 태그 자동완성. `allTags()`가 이미 워크스페이스 전체 태그를 세고 있다
- 텍스트를 선택한 채로 `*` `` ` `` `(` `[` → 감싸기
- `**` `` ` `` `[` 자동 닫기

#### (d) 블록 수준

- **멀티라인 코드 블록**: 행 텍스트는 한 줄이 원칙(= textarea 하나)이므로
  **메모 안의 ``` 펜스**로 두는 게 맞다. 하이라이터는 나중 문제다
- **인용**
- **이미지**: `![](url)`을 렌더한다. 원격 URL은 토큰 하나다. 업로드는 §5에서 다룬다

#### (e) 코드 에디터 관용구

우리는 한 줄이 곧 한 항목이라 "줄 조작"이 그대로 "항목 조작"이 된다.

- **⌘D 항목 복제**, **⌘⇧K 항목 삭제**: 지금은 Esc로 선택 모드에 들어가야만 항목을 지울 수 있다
- ⌘] / ⌘[ 들여쓰기 (Tab을 보조하는 키로, 폰이 아니라 손이 홈 포지션에 있을 때 쓴다)
- URL을 붙여넣으면 선택한 텍스트가 `[선택](URL)`이 된다
- ⌘⇧V 서식 없이 붙여넣기

#### 키 충돌 — ⌘K를 비워야 한다

마크다운 에디터에서 ⌘K는 링크를 넣는 키다. 지금은 이 키를 검색이 쓰고 있다. §2.3에서 팔레트를 코드 에디터
관례로 옮기면 이 충돌은 자연히 풀린다:

| 키 | 지금 | 제안 |
| --- | --- | --- |
| ⌘P | — | 팔레트 (문서·항목) |
| ⌘⇧P | — | 팔레트 (명령) |
| ⌘⇧F | — | 워크스페이스 전체 검색 |
| ⌘F | 검색 | **문서 내 필터** (§2.5) |
| ⌘K | 검색 | **링크** |
| ⌘/ | 도움말 | 유지 (코드 에디터의 주석 토글은 여기서는 쓸 데가 없다) |

⌘K가 손에 익은 사람이 있으니, 당분간은 팔레트도 ⌘K를 함께 받는 편이 낫다. 키맵을 별도 테이블로 분리하면
(지금은 `useOutline.ts`에 하드코딩되어 있다) 이 결정을 나중에 사용자에게 넘길 수 있다.

> **2026-08-20 후기.** 위 표가 그대로 기본값이 되었고, 마지막 문장도 실제로 그렇게 되었다:
> "사용자에게 넘긴다"가 **프리셋**의 형태가 됐다. 이 표는 `editor` 프리셋이고, Dynalist의
> 키(⌘] = 확대, ⌘⇧1~6 = 색)를 그대로 쓰는 `dynalist` 프리셋이 함께 있다. 두 관례는 같은 키를
> 다르게 쓰므로 한 표로는 양립하지 않는다. 그래서 기본값을 뒤집는 대신 표를 하나 더 두는
> 쪽을 택했다 ([ADR-0006](./adr/0006-keymap-presets.md)).

### 2.3 팔레트 — 뼈대는 이미 있다

**원하는 모양은 이미 절반 이상 만들어져 있다.** `⌘K`가 여는 `SearchPanel`은 화면 중앙
(정확히는 상단에서 12vh)에 뜨는 오버레이 모달이다. 맨 위의 검색 입력과 그 아래의 결과, ↑↓ 이동, Enter로 열기,
Esc로 닫기, 포커스 트랩과 복귀까지 `Panel.tsx`에 들어 있다. 이는 VS Code의 Quick Open과 같은 골격이다.

코드 에디터의 팔레트와 다른 것은 **골격이 아니라 안에 든 것**이다.

| 없는 것 | 왜 중요한가 |
| --- | --- |
| **명령 실행** | 지금 내보내기·가져오기·테마·동기화 설정·모두 접기가 전부 `⋯` 메뉴에만 있다. 마우스로만 접근할 수 있는 기능이 남아 있으면 "키보드로 다 된다"가 깨진다. 팔레트가 이 기능들을 흡수해야 한다 |
| **접두사 모드** | `>` 명령, `#` 태그, `@` 항목, 접두사가 없으면 문서. VS Code Quick Open 방식 그대로다. 지금은 노드 텍스트 검색 한 종류뿐이다 |
| **퍼지 매칭** | 지금은 부분 문자열 검색(`haystack.includes`)이라 `sc.ts` 같은 입력이 안 걸린다 |
| **매치 하이라이트** | 왜 이 결과가 나왔는지 안 보인다 |
| **빈 쿼리 = 최근 항목** | 지금은 "검색어를 입력하세요"라는 문구가 뜬다. 팔레트는 열자마자 최근 문서가 보여야 한다 |
| **결과 종류 표시** | 문서 / 항목 / 명령 / 태그가 섞이면 구분이 필요하다 |
| **점수 정렬** | 지금은 문서 순서대로 훑고 활성 문서만 앞에 둔다 |
| 결과 가상화 | 200개 제한으로 막고 있다. 결과가 뷰가 되면(§2.5) 제한이 걸린다 |

`search.ts`는 그대로 두고 그 위에 스코어링과 명령 레지스트리를 추가하는 일이라 **데이터 변경이 0이다.**

### 2.4 항해 — 문서가 늘면 무너진다

사이드바는 접을 수 있고(`⌘\`), 문서 목록·이름 변경·순서 변경·태그 구름이 있다. 문서가 다섯 개일 때까지는
이것으로 충분하지만, 쉰 개가 되면 감당하지 못한다.

| 빠진 것 | 구현 방향 |
| --- | --- |
| **폴더** | `Doc`에 `parent: Id \| null`을 두고 기존 `sort` 분수 인덱스를 함께 쓴다. 폴더도 같은 테이블의 레코드(`kind: "folder"`)로 두면 **정렬·이동·삭제·병합이 전부 공짜로 따라온다**. 이는 노드 트리에서 이미 검증된 패턴이다. GitHub 레이아웃은 그대로 평평하다(`docs/{id}.json`). 폴더 소속은 문서의 필드일 뿐 경로가 아니기 때문이다 |
| **즐겨찾기** | 워크스페이스 레벨에 `bookmarks`를 둔다. 문서·항목·검색어 셋 다 가리킬 수 있어야 하고, 같은 `sort`+묘비 패턴으로 병합된다. **`views`에 넣으면 안 된다**. `views`는 기기 로컬이고 즐겨찾기는 사용자 자산이기 때문이다 |
| **문서 간 항목 이동** | 아래 주의 |

**문서 간 이동에는 순서 규칙이 하나 필요하다.** `tree.ts`의 연산은 전부 한 `Doc` 안에서 동작한다.
A → B 이동은 A에 묘비를 쓰고 B에 삽입하는, 두 문서에 걸친 편집이다. 노드 id는 UUID라 그대로
가져가면 되지만 병합은 문서별로 이루어지기 때문에, **B만 받고 A를 아직 못 받은 기기는 같은 항목을 두 곳에서
본다.** 수렴은 다음 주기에 이루어지므로 데이터가 깨지지는 않는다. 하지만 순서 규칙은 DESIGN.md의 "묘비를 먼저 쓴다"와
같은 계열로 명시해야 한다: **A의 묘비가 B의 삽입보다 먼저 푸시된다.** 순서가 반대면 중간에 읽은 기기가
원본을 "내가 올려야 할 것"으로 보고 되살린다.

### 2.5 검색이 곧 뷰

이것은 §2.3의 팔레트와 **다른 것**이라 따로 둔다. 팔레트는 "가서 열기"이고, 이건 "여기 남아서 걸러내기"다.

다이나리스트의 문서 내 검색은 화면을 그대로 두고 **매치되지 않는 줄만 지운다.** 조상은 맥락으로
남고, 남은 줄은 **그 자리에서 편집된다.** 그래서 검색이 "찾기"가 아니라 "임시로 만든 뷰"가 된다.

구현은 `rows` 파생 단계에서 매치된 노드와 그 조상만 남기는 것이다. 데이터 변경은 0이고
`useVirtualRows`와 그대로 맞물린다. **편집이 그대로 되는 게 핵심**이라 별도 렌더 경로를 만들면 안 된다.

같이 필요한 것이 **검색 연산자**다. 팔레트와 필터 뷰 양쪽이 같은 파서를 쓴다.

| 연산자 | 지금 | 필요한 것 |
| --- | --- | --- |
| `#태그` | ✅ (계층 태그까지) | — |
| `is:completed` / `is:incomplete` | ❌ | `done`을 읽기만 하면 된다 |
| `has:note` / `has:link` / `has:image` | ❌ | 파싱만 하면 된다 |
| `-제외`, `"따옴표 구절"` | ❌ | 쿼리 파서 |
| `edited:3d` | ❌ | `edited.at`을 읽기만 하면 된다 |
| `created:3d` | ❌ | `created` 스탬프가 없다 (§7) |
| `parent:` / `ancestor:` | ❌ | `ancestors()`가 이미 있다 |

`within:`(날짜 범위)는 §5에서 뺀다.

### 2.7 오프라인 — 신뢰의 문제

매니페스트가 있어 홈 화면에 추가할 수는 있지만 **셸을 캐시하지 않아서 신호가 없으면 빈 화면이 뜬다.**
노트는 이미 IndexedDB에 다 있는데도 그렇다. 로컬 우선을 표방하면서 오프라인으로 안 열리는 건
그 자체로 모순이라 P0다. 필요한 것은 service worker 하나다. CSP는 이미 `script-src 'self'`라서 충돌이 없다.

딸려오는 것: 매니페스트에 **Web Share Target**을 선언하면 폰의 공유 시트에서 바로 인박스로
캡처가 들어온다. 즉 네이티브 앱 없이 퀵 캡처를 얻는다.

### 2.8 안전망

| 다이나리스트 | 우리 | 격차 |
| --- | --- | --- |
| 버전 히스토리 (Pro) | **모든 푸시가 커밋이다.** 문서마다 파일이 하나라서 diff가 읽힌다 | 데이터 면에서는 이미 우리가 낫다. 하지만 **앱 안에서 볼 수가 없다**. 그래서 커밋 목록 → 미리보기 → 복원 패널이 필요하다. API 호출 하나면 된다 |
| 자동 백업 (Pro) | 리포 자체가 백업이고, JSON 내보내기도 있다 | 없음 |

**휴지통은 묘비와 정면으로 충돌한다.** `graves`는 `Record<Id, Stamp>`라서 id와 시각만 있고

맡는다. 대신 **문서 단위 휴지통**은 값어치가 있다. 실수로 문서를 지우면 지금은 되돌릴 길이

## 3. 데이터 이주 — 옮겨오지 못하면 나머지는 의미 없다

기능이 다 있어도 **기존 노트가 그대로 넘어오지 않으면 아무도 옮기지 않는다.**
다이나리스트는 노트를 OPML / 서식 있는 텍스트 / 일반 텍스트 형식으로 내보낸다.

지금 `formats.ts`의 OPML 가져오기가 읽는 것은 `text`, `_note`, `_complete`, `_collapsed`다.
**버려지고 있는 것**은 색 라벨, 체크리스트·번호 목록 표시, 제목 수준, 그리고 항목 id(내부 링크의 대상)다.

1. 다이나리스트 내보내기 실물을 픽스처로 **왕복 테스트 고정**
2. §2.1의 필드가 들어오는 대로 OPML 매핑 추가
3. **항목 id 보존**: id를 보존하지 않으면 다이나리스트 안의 내부 링크가 전부 끊긴다
4. 문서 여러 개를 **한 번에** 가져오기 (지금은 파일을 하나씩 가져온다)
5. 폴더 구조 보존 (§2.4가 선행되어야 한다)

**§2.1과 §2.4가 먼저 있어야 이주가 손실 없이 끝난다.** 순서가 여기서 결정된다.

> **2026-08-21 실사와 그 뒤의 작업: 5개 중 4개가 끝났고, 남은 하나는 실물 파일을 기다린다.**
> 실사는 코드를 직접 확인한 결과이고, 그 뒤 항목은 그때 착수한 작업의 결과다. 남은 일의
> 계획은 [PLANS.md](../PLANS.md)에 있다.
>
> | # | 항목 | 실제 |
> | --- | --- | --- |
> | 1 | 실물 픽스처 왕복 테스트 | ❌ **안 됐고, 코드로 끝낼 수 없다.** `transfer/__tests__/formats.test.ts`가 쓰는 것은 손으로 쓴 OPML 한 줄이고, 속성 철자(`note`·`complete`·`colorLabel`·`checkbox`·`numbered`)는 **추정**이다. 임포트 충실도 전체가, 실제 Dynalist 파일과 한 번도 대조해 본 적 없는 가정에 기반하고 있다. 그래서 **사용자가 내보내기 파일을 줘야 한다** |

## 4. 항목 단위 내부 링크

지금 `[[...]]`는 **문서 제목**을 가리킨다. 다이나리스트의 `[[`는 **항목**을 가리키고, 이 기능이 항목들을
서로 이어 주기 때문에 "모든 것이 아웃라인 안에 있다"가 성립한다.

노드 id가 이미 전역 유일한 UUID라 조건은 갖춰져 있다. 필요한 것은 (1) 링크 토큰이 id를 싣는 것,
(2) 워크스페이스 전역 id→(문서, 노드) 인덱스(`allTags()`가 이미 같은 모양으로 전 문서를 훑는다),
(3) 대상이 삭제되어 묘비만 남았을 때 깨진 링크를 조용히 지우지 않고 표시하는 것이다.

**백링크**("이 항목을 가리키는 곳")는 그 인덱스를 뒤집으면 파생된다. 스키마 변경은 0이다.
다이나리스트에는 기본으로 없는 기능이라, 우리가 앞설 수 있는 지점이기도 하다.

§2.2(c)의 `[[` 자동완성이 이 링크를 입력하는 경로다.

## 5. 하지 않을 것 (그리고 그 이유)

| 기능 | 왜 안 하는가 |
| --- | --- |
| **날짜·일정·반복·캘린더 연동** | **2026-09-29에 절반이 들어왔다** ([ADR-0012](./adr/0012-dates-as-text.md)): `!(날짜)` 표기의 렌더·검색과 `!!` 입력이다. 알림·반복 계산·캘린더는 여전히 뺀다. 아래는 당시의 판단이다. **범위에서 뺀다** (사용자 결정). 다이나리스트에서는 핵심 기능 중 하나이지만, 이 도구가 지향하는 것이 아니다. 할 일은 체크박스와 태그로 충분하다. 따라오는 것들도 같이 빠진다: 날짜 선택기, 상대 표기, 지난 항목 강조, `within:` 검색, `.ics`/캘린더 |
| 편집 중 WYSIWYG | 다이나리스트는 편집 중에도 서식이 보인다. 그러려면 contenteditable이 필요하고, 그러면 **한글 IME 조합이 깨진다**. 원문↔렌더 전환 모델을 유지한다 (§2.2) |
| 실시간 공동 편집, 사용자 간 공유 | 병합은 클라이언트에서 이루어지고, 계정이 없다. 병합을 서버가 판정하게 만드는 순간 **E2EE가 불가능해지고 GitHub 백엔드도 불가능해진다** (`HANDOVER.md` 결정 2) |
| 공개 링크 공유 | 위와 별개로 가능은 하다: 문서를 정적 HTML로 내보내 Pages에 올리면 서버 없이 읽기 전용으로 공유할 수 있다. 우선순위는 낮다 |
| ~~파일 첨부~~ | **했다.** 봉한 blob을 `<img src>`로 걸 수 없다는 점은 맞다. 그래서 노트와 같은 인증·복호 경로로 첨부를 받아 object URL로 만든다. 리포가 커지는 대가는 그대로 남지만, 1MB 상한과 내용 해시 이름으로 그 대가를 줄였다 |
| 글자 단위 동시 편집 병합 | DESIGN.md에 적힌 알려진 한계 그대로다. 개인 기기 사이의 왕복에서는 맞는 트레이드오프다 |

| 인용과 코드 블록 | `> `는 행의 속성이고, ``` 펜스는 메모 안에 둔다. 메모도 이제 원문↔렌더로 전환된다 |
| 이미지 인라인 | 원격 URL과 첨부를 둘 다 지원한다 |

### 하나 안 한 것: Tauri

> 이 결정은 **2026-09-29에 뒤집혔다** ([ADR-0010](./adr/0010-native-shell.md)). 사용자가 설치되는 앱과
> "파일 하나를 정본으로 주고받는" 동기화를 원했고, 뒤의 것은 PWA로 채울 수 없었다. 근거는 셸이 더 주는 것이
> 아이콘에서 디스크에 있는 정본 파일로 바뀌었다는 점이다. 아래 문단은 당시의 판단으로 그대로 둔다.

PWA가 설치되고 오프라인으로 열리고 공유 시트까지 받는 지금, Tauri가 더 주는 것은
"작업 표시줄 아이콘"과 전역 단축키 정도다. 대가는 **Rust 툴체인과 플랫폼별 빌드 파이프라인**이고,
그것은 이 프로젝트가 지켜온 "의존성 0, 정적 파일 하나로 배포"라는 원칙과 정면으로 어긋난다.
Tauri가 필요해지는 순간이 오면 그때 판단할 일이지, 지금 치를 대가가 아니다.

## 7. 스키마 변경 총계 (구현된 대로)

아래 표는 P0·P1·P2 전부가 들어가는 데 든 **모델 변경의 전부**다. 예측이 맞았다:
**`merge.ts`에 새 규칙은 하나뿐이고, `SyncPayload`와 GitHub 파일 레이아웃은 그대로다.**

| 대상 | 필드 | 병합 규칙 |
| --- | --- | --- |
| `Node` | `checklist`, `numbered`, `color`, `bookmarked`, `quote` | `edited` LWW (기존) |
| `Node` | `created: Stamp` | **더 이른 쪽** (유일한 새 규칙) |
| `Doc` | `parent`, `kind: "doc" \| "folder" \| "search"`, `query`, `bookmarked`, `deleted` | `parent`는 `moved`, 나머지는 `titleEdited` |
| `Doc` | `inbox` (v7, 2026-08-21) | `titleEdited` LWW (새 규칙 아님) |
| `Workspace` | `keymap` (v8, 2026-09-01) | 표 **전체**를 `edited` LWW로 병합한다. 고른 적 없는 쪽(`null`)은 고른 쪽을 이기지 못한다 ([ADR-0008](./adr/0008-keymap-travels.md)) |
| `DocView` | `hideCompleted`, `hideNotes`, `filter` | 동기화 안 함 (기기 로컬) |

계획에서 **바뀐 것이 둘** 있다:

1. **즐겨찾기를 워크스페이스 목록이 아니라 노드·문서의 플래그로.** `SyncPayload`도
   `remote.ts`의 파일 레이아웃도 손댈 필요가 없고, 병합은 기존 LWW를 그대로 따른다.
2. **저장된 검색을 문서로.** 1번 때문에 검색어를 담을 자리가 없어졌는데, `kind: "search"`인
   문서로 두니 폴더와 똑같이 **정렬·이동·삭제·병합이 전부 공짜**가 됐다. 결과적으로 처음
   계획했던 워크스페이스 레벨 목록보다 낫다. 저장된 검색을 폴더에 넣을 수도 있고, 즐겨찾기할 수도 있기 때문이다.

**휴지통도 스키마를 안 늘렸다.** 묘비는 내용을 담고 있지 않아서 복구가 원리적으로 불가능하다.
하지만 `deleted` 스탬프 하나로 "파일은 그대로 두고 숨긴다"가 가능해지므로 복구가 공짜가 된다. 묘비 TTL이
지나면 이 소프트 삭제는 진짜 삭제로 승격된다.

백엔드에는 `history`(커밋 읽기)와 `files`(첨부)라는 **선택적 능력** 둘이 추가되었다. 둘 다 GitHub 백엔드만
가지고 있고, 이 점이 REST 백엔드와의 차이다. 전송 계약 자체는 안 바뀌었다.

§2.2의 서식은 **전부 `text` 안의 마크다운 문자열**이라서 여기에 없다. 이것이 서식을 인라인으로 두는 이유다
(내보내기에서 보존되고, 동기화 페이로드가 그대로다).

**공유 캡처의 도착지도 스키마를 안 늘렸다: 필드 하나로 끝났다.** `Doc.inbox`(v7)가 그 필드다.
이것이 워크스페이스 설정이 아니라 문서의 필드인 이유는 **기기 사이에 전달되어야** 하기 때문이다: 폰에서
캡처한 것을 데스크톱에서 찾는데, 기기 사이에 전달되는 것은 `SyncPayload`(= `docs` + `graves`) 안에 있는
것뿐이다. 이 값을 `activeDocId`처럼 워크스페이스 최상위에 두면 기기 로컬이 되어 기기마다 도착지가
달라진다. `titleEdited`를 따르므로 병합 규칙도 새로 생기지 않았다. 이는 `bookmarked`와 똑같은 수법이다.
대신 두 기기가 동기화되지 않은 동안 서로 다른 문서를 도착지로 표시할 수 있으므로 **하나로 정하는 것은
읽는 쪽**(`inboxDoc`)이 한다: 표시가 가장 새로운 문서를 택하고, 표시 시각이 정확히 같으면 id 순으로 정한다.
그래야 모든 기기가 같은 문서를 고른다.

`migrate.ts`는 v7까지 왔고 4→5→6→7은 전부 필드 추가뿐이라 **버전 올리기 한 줄씩**이다. 저장된
데이터는 언제나 `validate.ts`를 통과해 들어오고, 거기에 기본값이 있기 때문이다. 다만 `created`만은
기본값을 "지금"으로 두지 않고 **그 행의 마지막 편집 시각**으로 잡는다. 그렇게 하지 않으면 오래된 워크스페이스
전체가 `created:` 검색에서 갓 만든 것으로 보이게 된다.

## 8. 이미 우리가 나은 지점

- **버전 히스토리가 무제한이고 공짜다.** 다이나리스트에서는 Pro 기능이고, 여기서는 푸시가 곧
  커밋이다. 문서마다 파일이 하나라서 diff가 "무엇을 고쳤는지"를 그대로 보여 준다
- **종단 간 암호화.** 다이나리스트에는 없다
- **데이터가 내 것이다.** 서비스가 종료되어도 리포에 JSON이 남는다. 다이나리스트의 개발이 사실상
  멈춘 지금, 이것이 이 프로젝트가 존재하는 이유다
- **오프라인 편집이 손실 없이 병합된다.** 서버 없이, 순서와 무관하게
- **의존성 0** (react/react-dom 제외), 번들 93KB gzip. 수식을 쓰지 않는 워크스페이스는
  katex 청크를 한 바이트도 받지 않는다
- **한글 IME가 브라우저 기본 동작 그대로** 작동한다. 이것은 에디터 프레임워크를 쓰지 않은 대가로 얻은 것이다
