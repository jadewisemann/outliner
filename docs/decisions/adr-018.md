# ADR-018: Stage 1은 Obsidian식 다중 문서 워크스페이스로 전환한다

- 상태: 확정
- Supersedes: ADR-015의 "파일/폴더/다중 문서 시스템 제외" 중 다중 문서 제외 결정
- 결정: Stage 0 MVC 완료 이후 제품 코어는 단일 문서 아웃라이너가 아니라 Obsidian식 다중 문서 workspace로 확장한다. 기본 모델은 `Workspace -> Documents -> Nodes`이며, `[[Document]]`는 문서 링크, `[[Document^Node]]`는 문서 내부 노드 링크로 해석한다.
- 이유: 단일 문서 아웃라이너만으로는 내부 링크와 backlinks의 가치가 제한된다. 사용자가 기대하는 Obsidian식 지식관리 경험은 문서 생성, 문서 간 링크, 문서 내부 block 링크, workspace-wide search/backlinks가 함께 있어야 자연스럽다.
- 영향: Phase 16은 데스크톱/계정이 아니라 다중 문서 workspace foundation으로 재정의한다. 데스크톱/계정/sync 제품화는 Stage 2로 미루고, 모바일과 graph/alias/transclusion/attachments는 Stage 3 이후로 둔다.
- 링크 원칙: 사용자는 제목으로 링크하지만 시스템은 stable id로 저장한다. 링크 source text는 보존하고, picker는 생성/해결/중복/깨짐 상태를 명시한다.
- 제외 유지: 태스크 관리, 공유/협업 권한 모델은 계속 제품 핵심에서 제외한다. 전통적인 파일/폴더 pane, graph view 고도화, aliases, transclusion/embed, attachment vault는 추후 확장이다.
