# ADR-017: 원격 저장소는 realtime보다 저비용 개인 sync를 우선한다

- 상태: 확정
- 결정: 중기 원격 sync는 항상 켜진 realtime stream보다 저비용 개인 다기기 sync를 우선한다.
- 이유: 제품 범위는 다중 사용자 공동편집이 아니라 개인 다기기 동기화다. 이 경우 초 단위 공동편집보다 앱 시작, 포커스 복귀, 수동 저장, 짧은 debounce window에서 안정적으로 최신 상태를 맞추는 것이 더 중요하다.
- 구현 상태: Phase 12에서 앱 런타임은 `RemoteStoreV2` snapshot-primary sync와 optional patch capability로 전환했다. v2 adapter는 최신 snapshot 1개를 primary artifact로 저장하며, write는 version/client 기반 compare-and-swap semantics로 처리한다. 같은 base version을 가진 클라이언트는 full snapshot 대신 latest patch를 읽고 쓸 수 있다. 충돌 시 밀려나는 로컬 snapshot은 conflict backup에 저장하고 `conflict` sync 상태로 사용자에게 알린다.
- 단기 방침: 기존 v1 Firebase RTDB append-log adapter는 legacy/migration 경계로 남긴다. 기본 앱 설정은 `?remote=firebase`가 명시되어도 v2 adapter를 만든다.
- 중기 방침: Phase 12-C의 1차 비용 해법은 latest bounded patch + compacted snapshot 형태의 patch 경로다. patch가 없거나 base version이 맞지 않을 때만 latest snapshot으로 복구한다.
- 우선 후보: 현재는 `RemoteStoreV2` optional patch capability를 유지한다. 더 큰 비용 최적화가 필요하면 정적 snapshot/blob, metadata-only conditional write, chunked snapshot, 서버/API 기반 compaction을 별도 Phase에서 비교한다. Firebase RTDB realtime subscription은 기본 sync 방식으로 간주하지 않는다.
- 영향: Phase 12는 RTDB 최적화가 아니라 저장소 교체 가능한 sync protocol 경계로 완료한다. import/export와 history 기능은 원격 저장소 구현에 직접 의존하지 않는다.
