# 0004 — 수식은 KaTeX를 지연 로드한다 (의존성 0 정책의 유일한 예외)

- 상태: 승인
- 날짜: 2026-08 (P2 구현 시점의 결정, 2026-08-20에 ADR로 소급 기록)

## 맥락

`$$수식$$` 렌더가 P2 로드맵에 있었다 ([docs/parity.md](../parity.md) §6). 이 프로젝트의
런타임 의존성은 react/react-dom 뿐이고, 그것이 원칙이다 (DESIGN.md 원칙 12).

## 결정

`katex`를 의존성으로 추가하되 **지연 로드**한다. 수식이 없는 워크스페이스는 한 바이트도 받지
않고, 수식이 처음 나타날 때만 코드와 글꼴을 가져온다. 도착 전에는 원문(`$$…$$`)이 그대로
보인다. CSP에는 `font-src 'self'`만 열었다 — 번들에 동봉되므로 외부 호스트는 없다.

## 검토한 대안

- **수식 렌더 자체 구현:** TeX 레이아웃은 코드 하이라이팅처럼 50줄 근사가 성립하지 않는
  영역이다 — 근사 수식은 틀린 수식이다.
- **수식 미지원:** 가능했지만, 지연 로드가 "안 쓰는 사람은 비용 0"을 지켜준다면 굳이 뺄
  이유가 없었다.
- **무조건 번들 포함:** KaTeX는 앱 전체보다 네 배쯤 크다. 수식 없는 대다수 워크스페이스에
  그 비용을 물릴 수 없다.

## 결과

- 유일한 런타임 의존성 예외로 남는다. 다음 의존성 후보도 같은 기준을 통과해야 한다 —
  자체 구현이 성립하지 않고, 안 쓰는 사람의 비용이 0일 것.
- DESIGN.md 원칙 12와 「알려진 한계」에 반영됐다.
