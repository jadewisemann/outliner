# 0001 — 설계 문서를 정본으로 승격한다

- 상태: 승인
- 날짜: 2026-08-19

## 맥락

설계 근거가 `.dev.md`(아키텍처 산문)와 `HANDOVER.md`(세션 연대기)에 흩어져 있었고, 사실상
코드가 정본이었다 — 에이전트가 작업마다 코드에서 아키텍처와 불변식을 역추론했고, "조심할
것" 목록이 인수인계 문서에 갇혀 있었다.

## 결정

1. **`DESIGN.md`가 설계·불변식의 정본이다.** 코드는 How, 문서는 What / Why / Invariant.
   불변식은 diff만 보고 위반을 판정할 수 있는 문장으로 쓴다.
2. **기준선 동기화:** DESIGN.md는 커밋 `971b87b`(2026-08-19 기준 main)에서 추출해 코드와 한
   번 동기화했다. 권위가 문서로 넘어가는 것은 이 시점부터이며, 이후의 어긋남만 판정 대상이다.
3. **권위 규칙:** 문서와 코드가 충돌하면 조용히 코드를 따르지 않는다. 구현이 틀렸는지 설계
   의도가 바뀐 것인지 판정해 한쪽을 고치고, 근거를 `IMPLEMENTATION_NOTES.md`에 남긴다.
4. **예외 — 코드가 정본인 것들:** 기계가 소비하는 계약 파일(`src/types.ts`, `index.html`의
   CSP 값, `public/manifest.webmanifest`, `package.json`, `.github/workflows/pages.yml`)은
   계속 코드가 정본이고, 목록은 DESIGN.md가 유지한다.
5. **문서는 사람과 에이전트가 함께 수정한다** — 사람은 의도가 바뀔 때, 에이전트는 작업
   사이클의 Reconcile 단계에서 현실을 반영할 때. 둘 다 PR 리뷰를 거친다.
6. **커밋 게이트 훅**(`.claude/hooks/design-review-gate.mjs`)이 Reconcile 검토를 강제한다 —
   강제되는 것은 문서 수정이 아니라 문서와의 일관성 검토다.

## 검토한 대안

- **코드 정본 유지 + 주석 강화:** 불변식이 여러 파일에 흩어져 diff에서 보이지 않고,
  에이전트의 역추론 비용이 매 작업마다 반복된다.
- **HANDOVER.md 연대기 계속 쌓기:** append-only 서사는 "지금 무엇이 참인가"라는 질의에
  부적합하고, 커질수록 컨텍스트를 먹는다.

## 결과

- `.dev.md`는 실행법·기능·배포 문서로 역할이 좁아지고, 설계 서술은 DESIGN.md와
  `docs/design/*`로 이관됐다.
- `HANDOVER.md`는 갱신을 멈춘 아카이브로 격하됐다 — 결정은 ADR로, 함정·실측값은
  `docs/design/code-rationale.md`로, 남은 작업은 `PLANS.md`로 이관.
- `CLAUDE.md`는 `AGENTS.md`로 가는 포인터만 남는다.
