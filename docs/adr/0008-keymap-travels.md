# ADR-0008 — 단축키 표는 기기가 아니라 워크스페이스의 것이다

- 날짜: 2026-09-01
- 상태: 채택

## 맥락

[ADR-0006](./0006-keymap-presets.md)이 프리셋을 도입하면서 마지막 줄에 "키맵은 계속
`localStorage`의 기기 로컬 값이다"라고 적었다. 그 결과가 실사용에서 드러났다. Dynalist에서
옮겨온 사람이 노트북에서 `dynalist` 프리셋을 고르고, 폰을 열면 다시 `editor`이고, 데스크톱을
열면 또 `editor`다. 프리셋의 값은 **손에 익은 것을 지키는 데** 있는데, 기기마다 다시 골라야
한다면 그 값의 상당 부분이 사라진다.

DESIGN.md의 「알려진 한계」에도 이것이 한계로 적혀 있었고 PLANS.md 대기열 6번이 "프리셋을
기기 사이에서 옮기는 것"을 들고 있었다. 즉 의도된 트레이드가 아니라 미룬 일이었다.

## 결정

**단축키 표를 워크스페이스의 필드로 올리고 동기화 페이로드에 싣는다.**

```ts
type KeymapSetting = { keys: Record<string, string>; edited: Stamp };
type Workspace = { version: 8; docs; graves; keymap: KeymapSetting | null; … };
type SyncPayload = Pick<Workspace, "docs" | "graves" | "keymap">;
```

- 병합은 **표 전체를 한 번에** `edited` 스탬프로 판정한다. 한쪽의 절반과 다른 쪽의 절반을
  섞으면 누구도 고른 적 없는 표가 된다.
- 표를 고른 적 없는 기기(`null`)는 고른 기기의 표를 **빼앗지 않는다.**
- GitHub 백엔드에는 `{folder}/keymap.json`이 하나 는다. 문서를 문서마다 나눈 것과 같은
  이유다 — 바꾸지 않은 워크스페이스는 이 파일을 다시 쓰지 않고, 바꾼 커밋은 이름으로 그것을
  말한다.
- REST 백엔드는 페이로드가 문서 하나이므로 저절로 실린다.

## 왜 화면 설정은 따라가지 않는가

`appearance.ts`(글꼴·크기·줄 간격·본문 너비)와 테마는 **기기 로컬 그대로 둔다.** 판정의 축은
"설정이냐 데이터냐"가 아니라 **그 값이 기기에 속하는가, 사람에게 속하는가**다.

- 폰과 27인치 화면은 같은 본문 너비를 원하지 않는다. 측정값은 **화면의 것**이다.
- ⌘]를 확대로 익힌 손은 어느 기기에서나 그렇게 익혔다. 단축키는 **사람의 것**이다.

`Mod`가 이미 ⌘와 Ctrl을 흡수하므로, 맥과 리눅스가 서로 다른 표를 원할 이유도 남지 않는다.

## 왜 "프리셋 이름 + 덮어쓴 것"이 아니라 표 전체인가

`{ preset: "dynalist", overrides: { … } }`로 저장하면 나중에 프리셋에 액션이 하나 추가될 때
그 기본값이 자동으로 따라온다는 이점이 있다. 그렇게 하지 않았다.

- 앱과 재바인딩 패널이 주고받는 것이 이미 **완성된 표 하나**다(`Keys.tsx`, `Shortcuts.tsx`,
  `App.tsx`의 `bound()`). 저장 형식만 바꾸면 패널의 모델이 "표를 고친다"에서 "프리셋과 차이를
  고친다"로 바뀌고, 그건 이 변경이 하려는 일보다 크다.
- 이점으로 든 문제(새 액션이 `dynalist` 사용자에게 `editor` 기본값으로 붙는 것)는 **이번
  변경이 만든 것이 아니라 원래 있던 것**이다. `resolveKeymap`이 빠진 액션을 `DEFAULT_KEYMAP`
  에서 채우기 때문이고, 고치려면 별도의 결정이 필요하다.

## 이주와 호환

- 스키마 v7 → v8은 **필드 추가뿐**이라 버전 올리기 한 줄이다. 올라온 워크스페이스의 `keymap`은
  `null`이다 — 그 워크스페이스는 어떤 관례를 쓰는지 말한 적이 없기 때문이다.
- 기기에 저장된 표(`outliner:keys`)는 **남고, 워크스페이스가 표를 갖기 전까지 그 기기에
  적용된다**(`storedKeymap()`). 그래서 업그레이드가 누구의 바인딩도 조용히 되돌리지 않는다.
- `storedKeymap()`은 저장된 것이 없으면 기본값이 아니라 **`null`**을 돌려준다. 이 구분이
  없으면 한 번도 고른 적 없는 기기가 자기 기본값을 남의 선택 위에 밀어 올린다.
- 두 기기가 각자 업그레이드하면서 서로 다른 표를 들고 있을 수 있다. 그때는 나중에 고른 쪽이
  이긴다. 새 규칙이 아니라 문서 필드들이 이미 타는 LWW와 같다.

## 대가

- **동기화 페이로드가 자란다.** 지금까지 페이로드는 노트뿐이었고, 이제 표시 설정 하나가
  올라탄다. 이 문이 열린 이상 "그럼 이것도"가 이어질 수 있으므로, 위의 판정 축(기기의 것이냐
  사람의 것이냐)을 근거로 남긴다.
- **GitHub 백엔드에 파일이 하나 는다.** pull마다 조건부 GET이 하나 늘지만, 304는 rate limit에
  잡히지 않는다.
- **단축키를 바꾸면 커밋이 하나 생긴다.** 노트가 아닌 것이 히스토리에 남는다는 뜻이고,
  파일 이름과 커밋 메시지(`outliner: keyboard`)로 구분된다.
