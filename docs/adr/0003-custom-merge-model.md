# 0003 — 범용 CRDT 대신 자체 병합 모델

- 상태: 승인
- 날짜: 2026-08 (재작성 세션의 결정, 2026-08-19에 ADR로 소급 기록)

## 맥락

기기 간 동기화가 필요했고, 직전 산출물은 Yjs를 기반으로 9,200줄까지 커져서 통제 불능이었다.
클라이언트 병합(ADR-0002)을 전제로, 아웃라인이 실제로 요구하는 병합 성질이 무엇인지 다시
물었다.

## 결정

범용 CRDT 라이브러리를 도입하지 않고, 병합에 실제로 필요한 세 가지만 데이터 모델에 넣는다:

1. `parent` + `sort` 분수 인덱스 (형제 순서를 표현하며, 동시에 삽입한 줄이 둘 다 남는다)
2. 내용/위치 스탬프 분리 (편집과 이동이 서로를 지우지 않는다)
3. 묘비 (삭제된 줄이 오래된 기기에서 되살아나지 않는다)

병합은 `sync/merge.ts`의 순수 함수 하나다. 이 함수는 순서와 무관하고 멱등이며, 테스트로
고정되어 있다.

## 검토한 대안

- **Yjs 등 범용 CRDT:** 메커니즘의 규모가 요구보다 한 자릿수 크고, 의존성 0이라는 목표와
  충돌하며, 직전 산출물에서 실패를 경험했다.
- **글자 단위 병합:** 같은 필드에 대한 동시 수정까지 보존하지만 메커니즘의 규모가 한 자릿수
  커진다. 개인이 자기 기기들을 오가며 쓰는 용도에서는 필드 단위 LWW가 맞는 트레이드오프다.

## 결과

- 전송 계약이 "버전 붙은 JSON + CAS"로 줄어 REST와 GitHub 둘 다 백엔드가 된다.
- 같은 줄의 같은 필드를 동시에 수정하면 한쪽이 이긴다. 이는 수용한 한계이며, DESIGN.md의
  「알려진 한계」에 명시되어 있다.
- `children`은 파생 캐시로 유지한다(읽기가 병합보다 훨씬 잦다). 이 캐시의 일관성은 테스트가
  자동으로 검사한다.
