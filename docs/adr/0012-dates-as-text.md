# 0012 — 날짜는 텍스트 안의 표기이고, 일정 기능은 만들지 않는다

- 상태: 승인
- 날짜: 2026-09-29
- 일부 뒤집는 결정: [parity.md](../parity.md) §5 「날짜·일정·반복·캘린더 연동」

## 맥락

2026-08에는 날짜 계열 기능 전체를 범위에서 뺐다. 2026-09-29에 사용자가 "Dynalist의 모든 편집 기능"을
요구했다. Dynalist의 날짜는 `!(2026-09-29)`처럼 **행의 텍스트 안에 쓰이는 표기**이고, OPML로 내보낸
파일에도 그 형태 그대로 들어 있다. 그래서 지금까지 Dynalist에서 옮겨 온 노트는 날짜를 잃지는
않았지만, 날짜가 기호 묶음으로 보였고 검색할 수도 없었다. 이것은 PLANS.md가 경계해 온
「조용히 잃는 것」과 같은 계열의 문제다.

## 결정

1. **날짜는 원칙 14대로 `text` 안의 문자열이다.** 새 필드도, 스키마 변경도, 새 병합 규칙도 없다.
   가져온 Dynalist 노트는 아무 변환 없이 그 자리에서 날짜로 보인다.
2. **렌더링**: `!(YYYY-MM-DD)`, 그리고 시간이 붙은 `!(YYYY-MM-DD HH:MM)`을 읽는다. 괄호 안에서 날짜
   뒤에 오는 것(Dynalist의 범위·반복 규칙)은 해석하지 않고 그대로 보여 준다. 규칙을 짐작해서 틀리게
   보여 주는 것이 원문을 보여 주는 것보다 나쁘기 때문이다. 가까운 날은 「오늘」「내일」「어제」로,
   나머지는 요일을 붙여 쓴다. 지난 날짜는 따뜻한 색이고, 오늘부터 7일 안의 날짜는 강조색이다.
3. **검색**: `date:today`·`date:overdue`·`date:tomorrow`·`date:7d`·`date:2026-09-29`, `has:date`. 검색은
   행에서 **날짜로 그려지는** 첫 날짜를 읽는다. 코드 구간 안의 날짜는 코드로 그려지므로 검색에도
   걸리지 않는다.
4. **입력**: 단어 시작에서 `!!`를 치면 오늘 날짜가 들어가고 날짜 부분이 선택된다. 그대로 두면 오늘
   날짜가 되고, 덮어 치면 다른 날짜가 된다. "감사합니다!!"처럼 단어 뒤의 `!!`는 문장 부호로 남는다.
   팔레트에는 「오늘/내일 날짜 붙이기」가 있고, 이것이 Android 소프트 키보드에서 날짜를 넣는 경로다.
5. **만들지 않는 것**: 알림, 반복 일정 계산, 캘린더(`.ics`) 연동, 날짜 선택기. 이것들은 서버나 백그라운드
   실행을 요구하거나(알림), 규칙 해석기를 요구한다(반복). 날짜를 "보이게 하고 찾게 하는" 것까지가 이
   결정의 범위다.

## 결과

- 관계 표기(「오늘」)는 그리는 순간의 날짜를 기준으로 정해진다. 행은 메모이즈되어 있으므로, 창을
  밤새 열어 두면 어제를 기준으로 한 표기가 그대로 남는다. 그래서 아웃라인의 키를 날짜(`useDay`)로
  잡아, 자정이 되었을 때와 창이 다시 보일 때 새로 그린다. 자정에 한 행을 편집하고 있었다면 그 편집
  상태가 한 번 풀린다.
- 원문의 글자 수와 화면에 그려진 글자 수가 다르기 때문에, 클릭 위치를 원문 위치로 옮기는
  `sourceOffset`이 날짜 라벨의 길이를 반영한다.
