# 0007 — 읽을 수 있는 Markdown 사본은 파생물이고, 암호와 함께 갈 수 없다

- 상태: 승인
- 날짜: 2026-08-29

## 맥락

노트를 파일로 두자는 요구의 실질은 **복구성**이다. 앱이 죽거나 스키마 이행이 잘못되어도
저장소만 있으면 노트를 읽을 수 있어야 한다. 지금 GitHub 백엔드는 문서당 파일 하나를
커밋하므로 그 절반은 이미 갖춰져 있다. 빠진 것은 그 파일이 사람이 읽을 수 있는 형식이 아니라는
점뿐이다.

앞선 검토에서 Markdown을 **정본**으로 삼는 방안도 함께 살펴본 뒤 기각했다. 기각한 근거는
[logseq-prior-art.md](../research/logseq-prior-art.md)에 있다. 요지는 세 가지다.

1. 아웃라이너 상태의 상당 부분(`collapsed`·`color`·`bookmarked`·`sort`·스탬프 세 개,
   `DocView`의 확대와 필터)은 Markdown에 들어갈 자리가 없다.
2. 그런 상태를 파일에 적으면 파일이 지저분해진다. Logseq이 `collapsed:: true`와 `id::`를 본문에
   적었고, 그 때문에 평문 Markdown을 고른 이유가 약해졌다.
3. Logseq은 결국 데이터베이스를 정본으로 삼는 쪽으로 분기했고, 그 뒤에 파생 Markdown 미러를
   다시 들여왔다(Logseq의 ADR 0016).

## 결정

**`.json`이 정본이고, `.md`는 그것의 파생물이다.**

1. GitHub 백엔드가 문서마다 `{폴더}/markdown/{제목}.md`를 함께 커밋한다.
2. **앱은 이 파일을 읽지 않는다.** 앱 밖에서 고쳐도 노트에 반영되지 않고, 다음에 저장할 때
   덮어써진다. 즉 양방향 동기화가 아니다.
3. **기본값은 꺼짐이고, 동기화 설정의 토글로 켠다.** 끄면 이미 만들어진 사본을 지운다. 그래서
   끄기는 수동적인 동작이 아니다.
4. **암호가 걸려 있으면 켜지지 않고, 이미 있는 사본을 지운다.** 이것이 이 결정의 유일한
   불변식이다.
5. 파일 집합은 푸시할 때마다 payload에서 **통째로 다시 계산한다.** 이전에 무엇이 있었는지
   기억하지 않으므로, 오랫동안 동기화하지 않은 기기도 한 번의 푸시로 수렴한다.
6. 미러 쓰기에 실패해도 문서 푸시는 실패하지 않는다. 파생물이 없어지는 것은 읽는 사람이 편의를
   잃는 일이지, 노트를 잃는 일이 아니다.

### 왜 암호와 함께 갈 수 없나

암호를 걸면 모든 파일이 기기를 떠나기 전에 봉해진다. 그 옆에 평문 `.md`를 두면 저장소를 가진
쪽이 노트를 전부 읽을 수 있게 된다. **암호가 막으려던 것을 미러가 그대로 열어 준다.** 그래서
이것은 설정 조합의 문제가 아니라 불변식이고, 판정은 UI가 아니라 백엔드에서 한다. UI에서 토글을
비활성화하는 것은 편의일 뿐이고, 보장은 `github.ts`의 `enabled`가 맡는다.

## ADR-0005의 선과의 관계

ADR-0005는 "저장소 백엔드에만 있는 능력을 더 늘리지 않는다"라고 명시했다. 이 결정은 그 선을
넘지 않는다.

- **계약 표면이 늘지 않았다.** `Backend` 타입에 `history`·`files` 같은 새 멤버가 생기지
  않았다. 미러는 GitHub 백엔드의 `push` 안에서 끝나고, 바깥에서는 보이지 않는다.
- **저장소의 본성에서 공짜로 나온다.** ADR-0005가 인정한 (b)에 해당한다. 커밋이 곧
  히스토리이고 파일이 곧 첨부 저장소인 것과 같은 이유로, **폴더가 곧 사람이 읽을 자리**다.
  URL 하나뿐인 REST 백엔드에는 그런 자리가 없다.
- **REST 사용자가 잃는 기능이 없다.** 미러는 파생물이므로 REST 백엔드에서도 노트와 동기화는
  그대로다. 이것은 히스토리 패널이 비는 것과는 층위가 다른 문제다.

## 검토한 대안

- **Markdown을 정본으로 삼는다:** 위 맥락 절에서 든 세 가지가 근거다. 아웃라이너 경험을
  지키려면 파일에 메타데이터를 적어야 하고, 그러면 평문을 고른 이유가 사라진다.
- **이름을 `{id}.md`로 짓는다:** 이름-정체성 문제는 사라지지만 사람이 읽을 수 없는 이름이
  된다. 미러가 존재하는 이유는 사람이 읽을 수 있게 하는 데 있으므로, 이 방식은 목적과 어긋난다.
- **이름-정체성 인덱스 파일을 둔다:** Logseq ADR 0016이 규정한 방식이다. 경로는 안정되지만
  파일이 하나 늘고, 그 파일도 CAS로 관리해야 한다. 파생물의 경로를 위해 그만한 비용을 들이지
  않기로 했다. 대신 푸시할 때마다 전체를 다시 계산해서, 경로가 바뀌더라도 **고아 파일이 생기거나
  다른 문서의 내용을 덮어쓰는 일이 없게** 했다. Logseq에서는 이 인덱스가 규정에만 있고 구현에는
  없어서, 같은 제목의 페이지가 생기면 기존 경로의 번호가 조용히 다시 매겨진다.
- **실시간에 가깝게 쓴다:** 이미 그렇게 동작한다. 미러는 동기화 푸시 때 함께 기록되므로 케이던스가
  10초와 30초이고, 편집 경로 밖에서 처리된다. 그래서 별도의 디바운스 장치는 두지 않았다.

## 결과

- **얻는 것:** 앱 없이 저장소만으로 노트를 읽을 수 있다. GitHub 웹에서도 읽을 수 있고, 클론해서
  아무 편집기로나 열 수 있다.
- **잃는 것:** 저장소 크기가 대략 두 배가 된다. 이 비용은 미러를 켠 사람만 치른다.
- **알려진 한계:** 같은 제목의 문서가 새로 생기면 기존 문서의 사본 경로가 바뀔 수 있다. 경로는
  읽기에 충분할 만큼 안정적이지만, 링크를 걸 만큼 안정적이지는 않다. 이것은 파생 파일에 대해
  받아들인 한계다.
- **되돌리기:** 토글을 끄면 사본이 사라지고 저장소는 이전 상태로 돌아간다.
