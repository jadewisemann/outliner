# 0011 — 폴더 백엔드: 파일 하나가 정본이고, CAS가 없는 매체는 루프가 보정한다

- 상태: 승인
- 날짜: 2026-09-29

## 맥락

사용자는 "파일 하나를 정본으로 주고받는" 동기화를 선택지로 원했다. 가장 흔한 형태는 이미 쓰고 있는
iCloud Drive·Dropbox·Google Drive·OneDrive·Syncthing 폴더에 파일을 두는 것이다. 서버를 따로 운영하지
않아도 되고, 비용이 없고, 파일이 사용자 손에 남는다.

문제는 이 매체들이 전송 계약의 절반만 지킨다는 것이다. 계약은 "버전 붙은 JSON을 읽고 CAS로 쓴다"인데,
파일 동기화 서비스는 다른 기기의 사본으로 파일을 **묻지 않고 바꿔 치우거나**, 동시에 쓰인 두 사본을
**충돌 사본**으로 남긴다. 이 앱의 루프는 지금까지 "편집이 없고 원격에 버전이 있으면 푸시하지 않는다"로
빈 커밋을 막아 왔는데, 이 규칙은 CAS가 쓰기를 지켜 준다는 전제 위에 있다.

## 결정

1. **새 백엔드 `kind: "file"`** (`src/sync/api/remote/file.ts`, 디스크 쪽은 `src-tauri/src/folder.rs`).
   고른 폴더에 `outliner.json` 하나를 두고, 형식은 REST 백엔드와 같다. 파일 하나를 옮기면 두
   백엔드 사이를 오갈 수 있다. 데스크톱 셸에서만 제공한다.
2. **CAS는 이 기기 안에서만 성립한다.** 셸이 쓰기 직전에 파일의 해시를 다시 읽어 비교하고, 임시
   파일에 쓴 뒤 rename으로 바꾼다. 다른 기기와의 경합은 이것으로 막을 수 없다.
3. **그래서 백엔드가 `unguarded`를 밝히고, 루프가 보정한다.** `unguarded` 백엔드에서는 편집이 없어도
   **원격이 이 기기가 가진 것을 빠뜨리고 있으면** 푸시한다. 판정은 `mergeWorkspace(원격, 로컬)`이 원격의
   객체를 그대로 돌려주는지로 한다(원칙 4의 객체 동일성). 누가 어떻게 덮어썼든 파일은 수렴한다.
   CAS가 있는 백엔드에는 이 검사를 켜지 않는다. 거기서는 CAS가 이미 같은 일을 하고, GitHub에서는 불필요한
   커밋이 될 수 있기 때문이다.
4. **충돌 사본은 읽어서 합치고, 합친 결과를 쓴 뒤에 지운다.** 사본 각각이 완전한 워크스페이스이므로
   병합이 순서 무관·멱등인 이상 합치는 것은 언제나 안전하다. 사본이 있으면 `Stored.rewrite`로 루프에
   다시 쓰기를 요청한다. **읽지 못한 사본은 지우지 않는다.** 원칙 8과 같은 계열이다: 없다고 판정할 수
   있는 것은 읽은 것뿐이다. 모르는 암호로 봉해진 사본이 있으면 `locked`로 멈춘다(원칙 7).
5. **사본의 이름 규칙은 `outliner` 다음에 공백·`.`·`-`·`(`·`_`가 오고 `.json`으로 끝나는 것이다.**
   서비스마다 이름이 다르기 때문에 넓게 잡았고, 그 대가로 **폴더는 이 앱 전용으로 둔다**고 안내한다.

## 검토한 대안

- **파일 하나를 사용자가 직접 고르게 한다:** 충돌 사본을 찾으려면 옆 파일을 볼 수 있어야 한다.
  폴더를 고르면 둘 다 된다.
- **문서당 파일(GitHub 배치)로 쪼갠다:** 충돌 범위는 줄지만 폴더 안의 파일 수와 묘비 파일 순서
  규칙(원칙 8)이 따라온다. 동기화 서비스는 히스토리를 주지 않으므로 쪼갤 이유가 GitHub만큼 크지
  않다. 워크스페이스가 커져서 아프면 그때 재검토한다([ADR-0009](./0009-delta-sync.md)의 조건과 같다).
- **파일 감시(watcher)로 즉시 반응한다:** 폴링 5초면 동기화 서비스의 전송 지연보다 짧다. 플랫폼별
  감시 코드와 그 실패 모드를 떠안을 값이 아직 없다.
- **Android에서도 제공한다:** Android는 폴더 경로가 아니라 content URI를 주고, `std::fs`로 다룰 수
  없다. 폰에서는 GitHub·서버 백엔드를 쓰거나 백엔드 없이 로컬로 쓴다.

## 결과

- 무료 동기화 선택지가 셋이 된다. GitHub 저장소, 동기화 서비스의 폴더, 무료 서버(Cloudflare Worker·
  레퍼런스 서버). 셋 다 병합은 기기에서 일어난다.
- 폴더를 공유하지 않아도 의미가 있다. 브라우저 저장소가 아닌 **디스크의 평범한 파일**에 사본이 하나 더
  생긴다.
- 알려진 한계: 두 기기가 같은 줄의 같은 필드를 동시에 고치면 한쪽이 이기는 것은 다른 백엔드와 같다.
  동기화 서비스가 파일을 옮기는 속도보다 빨리 서로 덮어쓰면 수렴이 몇 주기 늦어질 수 있다.
