# 0002 — 병합은 영원히 클라이언트에서 한다

- 상태: 승인
- 날짜: 2026-08 (재작성 세션의 결정, 2026-08-19에 ADR로 소급 기록)

## 맥락

동기화 설계 중 "Node 서버에서 병합을 판정하자"는 제안이 있었다. 서버가 판정하면 충돌 처리를
중앙에서 통제할 수 있어 보였다.

## 결정

병합은 언제나 클라이언트의 `sync/merge.ts`(순수 함수, 순서 무관·멱등)에서 일어난다. 백엔드는
"버전 붙은 JSON을 읽고 compare-and-swap으로 쓴다"는 계약의 저장소일 뿐, 내용을 판정하지
않는다.

## 검토한 대안

**서버 병합** — 논의 후 폐기:

- 서버가 필수가 되는 순간 "아무 GET/PUT 저장소"와 **GitHub 저장소를 백엔드로 쓸 수 없다.**
- 서버가 병합하려면 평문을 읽어야 하므로 **종단 간 암호화가 불가능하다.**
- 서버의 진짜 가치는 즉시 전파(SSE 핑)와 로그인뿐이라는 결론 — 그건 병합 위치와 무관하게
  나중에 얹을 수 있다.

## 결과

- 이 결정이 실제로 E2EE를 가능하게 했다 (`sync/api/cipher.ts`).
- GitHub contents API가 전송 계약의 구현체가 될 수 있었다 — 커밋 히스토리가 공짜 버전 아카이브.
- 대신 병합 정확성의 부담이 전부 클라이언트 모델에 있다 → [ADR-0003](./0003-custom-merge-model.md).
