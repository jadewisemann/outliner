# code-rationale — 실측값 · 함정 · 실패한 대안

**값을 바꾸거나 단순화하기 전에 해당 심볼을 여기서 먼저 찾아본다.** 코드 주석을 간결하게
유지하는 대신 근거를 이곳에 모아 둔다.

## 실측값

- **draft 패턴** (`entities/outline/model/tree.ts`): 연산마다 노드 맵 전체를 복사하면 1만 줄을 붙여넣는 데
  제곱 시간이 걸린다(실측 57초). 맵을 한 번만 얕은 복사하는 draft 방식에서는 1초 미만이다.
- **가상화 경계 250행** (`widgets/editor/model/useVirtualRows.ts`): 그 이하에서는 행을 전부 그려서 동작이 달라질
  여지를 없앤다. 측정값은 다음과 같다(Chromium, 개발 빌드).

  | 노드 수 | 붙여넣기 | DOM에 있는 행 | 키 입력당 동기 작업 |
  | --- | --- | --- | --- |
  | 2,000 | 0.66초 | 30 | 1.6ms |
  | 10,000 | 0.74초 | 30 | 5.6ms |

- **유휴 탭 6초간 DOM 변경 0건**이 기준선이다. 저장·알림은 타이머 폴링이 아니라 실제 변경에만
  반응하고, no-op 병합은 같은 객체를 돌려주므로 React가 렌더를 건너뛴다.
- **동기화 케이던스**(푸시/풀): REST는 1.5초/10초, GitHub는 10초/30초, 폴더는 1.5초/5초다. 값은 백엔드마다
  `cadence`에 들어 있다(`remote/rest.ts`·`github.ts`·`file.ts`). GitHub의 값은 커밋 소음과 rate limit 때문에
  이렇게 정했고, 조건부 GET이 받는 304 응답은 한도에 집계되지 않는다.
- **묘비 보존 30일**: 이보다 오래 꺼져 있던 기기는 지워진 줄을 되살릴 수 있다. 이 값은 묘비를
  영원히 보관하지 않기 위해 정한 것이다(DESIGN.md의 알려진 한계).

## 함정 (전적 있는 것 포함)

- **`UNBOUND`가 없으면 분기 순서가 승자를 정한다** (`entities/keymap/model/keymap.ts`). 두 액션에 같은 chord를
  바인딩해 두면 핸들러에서 먼저 검사되는 쪽이 이기고 다른 쪽은 아무 표시 없이 동작하지 않으므로,
  사용자는 원인을 알 방법이 없다. Dynalist 프리셋이 ⌘]를 확대에 할당하려면 들여쓰기 쪽에서 그 키를 **비워야**
  했고, 그래서 빈 문자열이 정식 값이 되었다. `loadKeymap()`에서 `bound !== ""` 검사를 되살리면
  프리셋에서 비워 둔 칸이 다음 로드에서 조용히 기본값으로 돌아간다.
- **숫자 키는 `event.code`로 맞춘다** (`PHYSICAL_KEYS`). Shift를 누르면 `1` 대신 `!`가 들어오므로
  색 라벨 ⌘⇧1~6을 `event.key`로 맞추면 **아예 안 걸린다.** 구두점 키도 같은 이유로 `event.code`로 맞춘다.
- **`csp.spec.ts`의 reload 앞에는 저장 대기가 필요하다.** 저장은 디바운스되고, `beforeunload`
  플러시는 navigation과 경합해서 진다. 그래서 대기가 없으면 **6회 중 1~2회** 실패한다(실측이며, 이 실패는
  기능의 문제가 아니라 스펙 안의 경합 때문이었다). `outline.spec.ts`의 reload 테스트가 600ms를 기다리는 것도
  같은 이유다.
- `children`은 `parent`/`sort`에서 파생된 캐시다. 둘 사이의 불일치는 `entities/outline/model/__tests__/tree.test.ts`의
  `shape()`가 모든 연산에서 자동으로 검사한다. 트리 연산을 추가하면 이 테스트를 통과해야 한다.
- 바깥에서 오는 데이터는 **반드시** `entities/outline/model/validate.ts`를 통과시킬 것.
- undo는 스냅샷 복원이 아니라 **재스탬프**다 (`entities/outline/model/history.ts`). 그렇지 않으면 다음 sync가 undo를
  되돌린다.
- 원격 병합 결과가 no-op인지는 **객체 동일성**으로 판별한다. 그래서 병합/트리 코드에서 객체를 불필요하게
  다시 만들면 유휴 리렌더 루프가 되살아난다 (전적: 유휴 탭이 분당 50회 리렌더).
- **`SyncPayload`에 필드를 더하면 세 곳을 함께 고친다.** 세 곳은 `payloadChanged`(`types.ts`, 동기화를 깨울
  편집인가), `changedBy`(`merge.ts`, 가져온 것이 있는가), 그리고 페이로드를 새로 조립하는
  `mergeWorkspace`의 `pruneGraves` 호출이다. 앞의 둘에서 필드가 빠지면 그 필드만 바꾼 편집이 푸시되지 않거나
  받아 온 값이 화면에 반영되지 않고, 마지막에서 빠지면 병합 결과에서 필드가 사라진다. v8에서 `keymap`을
  더할 때 세 곳 모두에서 이 함정에 걸렸다.
- **`lacks`는 정규화되지 않은 페이로드에서 거짓 양성을 낸다.** `children`이 이어지지 않은 픽스처는
  병합할 때마다 새 객체가 된다. 실제 워크스페이스는 늘 정규화되어 있어서(원칙 5) 문제가 없지만,
  테스트 픽스처는 한 번 병합해서 정규화한 뒤에 쓴다(`file.test.ts`의 `settled`).
- GitHub 백엔드에서 **파일 삭제는 묘비가 있을 때만 일어난다.** 파일이 페이로드에 없다는 것은 삭제의
  증거가 되지 못한다. 읽지 못한 파일도 페이로드에 없는 모습으로 나타나기 때문이다. 같은 이유로, 읽지 못하는
  원격(`locked`)에서는 푸시를 아예 멈춘다.
- 쓸지 말지는 **평문**을 기준으로 정한다(DESIGN.md 원칙 9). 암호문은 IV 때문에 매번 다르다.
- 가상화의 "포커스 행으로 스크롤"은 **새 포커스 요청(`seq` 변화)에만** 반응해야 한다. 창
  위치에 반응하게 만들면 편집 중인 행에서 스크롤해서 벗어날 수 없게 된다 (전적: 1초 뒤 편집 중인 행으로
  도로 스크롤되던 버그, 커밋 `413455e`).
- `Node` 타입 이름이 DOM의 `Node`를 가린다. 그래서 DOM을 함께 다루는 파일에서는 헷갈릴 수 있다.
- e2e는 웹 서버를 **둘** 띄운다 (dev 5173, `vite preview` 4173). `csp.spec.ts`와
  `install.spec.ts`는 빌드 결과(4173)를 상대로 실행된다. dev 서버에서는 CSP도 매니페스트도
  적용되지 않기 때문이다.
- **(환경) Playwright의 브라우저 핀과 이미지의 브라우저가 어긋나는 것은 정상이다.** 패키지를
  올리면 핀이 바뀌지만, 이미지는 자체 일정에 따라 바뀐다(실측: `@playwright/test` 1.60.0은
  `chromium-1223/chrome-linux64/chrome`를 찾는데 이미지에는 `chromium-1194/chrome-linux/chrome`만 있으며,
  빌드 번호도 디렉터리 규칙도 다르다). 어긋나면 **몇 개가 실패하는 것이 아니라 71개 전부가 launch 단계에서
  실패한다.** 이것은 e2e 신호가 0이 되는 실패이고, 에러가 "없는 경로"를 알려 줄 뿐 실제로 있는
  브라우저는 알려 주지 않으므로 가장 덜 유용한 실패다. 그래서 `playwright.config.ts`가 브라우저를 직접 찾는다. 찾는 순서는
  `PLAYWRIGHT_CHROMIUM_PATH` → Playwright 자체 빌드가 있으면 개입하지 않음 → `PLAYWRIGHT_BROWSERS_PATH`
  아래에 실제로 있는 최신 chromium이다. 한두 버전의 차이는 이 스펙들(평범한 DOM·키보드·CDP)에 무해하다.
  **`playwright install`로 풀지 말 것.** 이 이미지에는 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`이 설정되어 있다.
  GitHub 백엔드 e2e는 케이던스 때문에 `test.setTimeout(120_000)` 수준의 제한 시간이 필요하다.
- **`npm run typecheck`(`tsc --noEmit`)가 놓치는 걸 `npm run build`(`tsc -b`)가 잡는다.**
  테스트 파일과 e2e에 있는 타입 오류가 그렇다. 그러므로 커밋 전에 build를 한 번 돌릴 것. 전적: `spawn`에
  `stdio: ["ignore", "pipe", "pipe"]`를 주면 타입이 `ChildProcessWithoutNullStreams`가 아니라
  `ChildProcessByStdio<null, Readable, Readable>`이 되는데, 이 오류는 typecheck에서는 드러나지 않고 build에서 잡혔다.
- **키를 먼저 누르는 e2e 스펙은 `.row`가 보일 때까지 기다린다.** `page.goto("/")` 직후의 앱은 아직
  「불러오는 중…」만 그리고 있을 수 있고, 그때 누른 키는 아무 곳에도 전달되지 않는다. `.row`를 클릭하는 스펙에서는
  Playwright의 자동 대기가 이 대기를 대신해 준다. `settings.spec.ts`와 `keymap.spec.ts`의 `beforeEach`가
  이 대기를 두는 이유다 (전적: 2026-08-20에 flake로 보였던 실패).
- **데스크톱 뷰포트의 e2e에서 사이드바를 열려고 도구 막대 버튼을 누르면 닫힌다.** 900px보다 넓은
  창에서는 사이드바가 처음부터 열려 있기 때문이다(`App.tsx`의 `useState(() => window.innerWidth > 900)`).
- `view.focusId`는 **캐럿이 실제로 간 곳**이다(`requestFocus`가 기록한다). 팔레트의 행 명령과
  리로드 후 캐럿이 놓일 지점이 이 값을 읽으므로, 새 포커스 경로를 만들면 반드시 `requestFocus`를 통과시킬 것 (전적 있음).
- 자동 서식 되돌리기는 **그 규칙이 덮어쓸 필드만** 스냅샷해야 한다. 스냅샷할 필드를 고정해 두면 인용을
  되돌려도 인용이 남는다 (전적 있음).
- **`bulkPatch`는 이미 같은 값인 노드를 건너뛴다.** 건너뛰지 않으면 색 키를 두 번 누를 때마다 새 노드
  맵이 생겨 원칙 4의 객체 동일성이 깨진다. 이 동작은 테스트로 고정되어 있다.
- **`appendChild`는 비어 있는 마지막 자식을 다시 쓴다.** 방금 만든 문서에 퀵 캡처가 들어가면 둘째 행이
  아니라 그 빈 행에 쓰인다. 캡처가 `editWorkspace` 한 번으로 끝나는 것은 이 규칙에 의존한다.
- `inline.tsx`에서 컴포넌트를 `Math`로 이름 짓지 말 것. 전역 `Math`를 가리기 때문이다.
- 문서를 완전히 삭제할 때 남기는 묘비는 **지금 시각으로** 찍는다. `deleted` 스탬프(한 달 전일 수 있다)를
  그대로 쓰면 TTL이 이미 지나서 묘비가 바로 잊히고, 그 파일을 가진 기기가 문서를 되살린다.
- `inline.tsx`의 태그 규칙은 `TAG_SOURCE` **하나**다. `PATTERN`(렌더)과 `TAG_PATTERN`(추출)이
  각자 복사본을 가지고 있던 시절이 있었고, `@`를 넣으면서 그 복제가 두 배로 위험해졌다. 복사본이 어긋나면
  태그로 표시되는 것과 검색되는 것이 달라지기 때문이다. 시길을 늘릴 때 고치는 곳은 한 군데여야 한다.
- **`extractTags`는 토큰 우선순위를 모른다.** `renderInline`은 URL을 먼저 처리하므로
  `https://x.com/@user`가 링크 하나로 렌더되지만, 추출은 같은 줄에서 `@user`를 태그로 뽑아낸다. `#anchor`도
  예전부터 그랬다. 고치려면 추출도 `PATTERN` 전체를 거치게 해야 하고, 그러면 `**#work**` 안의 태그가
  검색에서 사라진다. 그 대가를 함께 결정하지 않은 채 "정리"하지 말 것.
- **폴더 피커는 `accept`를 무시한다.** `webkitdirectory` 입력은 찾은 파일을 전부 넘기고,
  `detectFormat`은 모르는 확장자를 `"text"`로 간주한다. 그래서 걸러내지 않으면 `.DS_Store`나 이미지가
  바이너리 쓰레기로 채워진 문서가 된다. 걸러내는 목록은 `IMPORT_EXTENSIONS`이고, 파일 입력의 `accept`도
  같은 목록을 쓴다.
- **`webkitdirectory`는 React prop이 아니다.** 또한 이 속성은 파일 피커를 폴더 피커로 **바꿔버리므로**
  한 입력이 둘을 겸할 수 없다. 그래서 숨은 입력을 두 개 둔다. 속성은 ref 콜백에서 붙인다.
- **`navigator.storage.persist()`는 앱을 켤 때마다 부른다.** 한 번 묻고 "아니오"를 기억하면 안 된다.
  Chrome은 설치·북마크·방문 빈도로 판정하므로, 첫 방문에서 거절당했더라도 그것이 확정된 답은 아니기 때문이다. `persisted()`가
  이미 true면 `persist()`를 부르지 않는다(부르면 Firefox에서 불필요한 프롬프트가 뜬다). API가 없는
  것과 거절당한 것은 `"unknown"`/`"best-effort"`로 **구분한다**. 모르는 것을 나쁜 소식으로
  보고하면 경고가 사실이 아닌 내용을 전하게 된다.
- **`--accent-fill`을 `--accent`로 합치지 말 것** (`app/styles/tokens.css`). systemBlue(`#007aff`) 위의
  흰 글자는 대비가 4.0:1이라 13px 글자에서는 AA 기준에 못 미친다. 위에 글자가 올라가는 채움(메뉴 강조, 기본 버튼, 팔레트
  선택)은 한 단계 짙은 `--accent-fill`(5.0:1, 어두운 테마에서 4.8:1)을 쓰고, 글자가 없는 채움(체크, 점,
  초점 고리)만 `--accent`를 쓴다.
- **색 라벨의 잉크는 `--ink-1`~`--ink-6` 하나다.** 행(`.row-cN`)과 행 메뉴의 견본(`RowMenu.tsx`)이
  같은 토큰을 읽는다. 견본이 hex 값을 따로 가지고 있던 시절에는 어두운 테마에서 견본과 행의 색이 달랐다.
- **REST 서버는 `Access-Control-Expose-Headers: etag`를 보내야 한다.** 이 헤더가 없으면 curl로는 정상인데
  브라우저에서만 `response.headers.get("etag")`가 `null`이 되고, `rest.ts`는 그것을 "원격에 아무것도
  없다"로 해석해서 모든 푸시를 조건 없는 쓰기로 보낸다. 동기화는 겉보기에 계속 동작하므로 드러나는 증상이 없다.
  `e2e/server.spec.ts`가 브라우저에서 직접 `fetch`해 헤더가 보이는지 확인하는 이유다.
- **레퍼런스 서버는 쓰기를 프로미스 하나로 줄 세운다.** 노드가 단일 스레드라고 해서 I/O 사이의
  원자성이 보장되지는 않는다. 줄 세우지 않으면 두 PUT이 모두 비교를 통과한 뒤 나중에 쓴 쪽이 조용히 이긴다.
- **`public/`의 파일을 바꾸면 `sw.js`의 `CACHE` 이름을 올린다.** worker는 탐색 요청이 아닌 모든 요청에
  캐시 우선으로 응답하는데, 이 방식은 "자산 이름에 내용 해시가 있다"는 전제를 바탕으로 한다. `public/`의 아이콘과
  매니페스트는 이름이 고정되어 있어서, `CACHE` 이름을 올리지 않으면 설치된 PWA가 옛 파일을 계속 받는다.
  `CACHE` 이름이 바뀌면 `activate`가 옛 캐시를 지운다.
- **`live.current`는 `applyWorkspace`가 동기적으로 갱신한다.** 그래서 한 tick 안에서
  `docs.createFolder`를 연달아 불러도 `nextSort()`가 서로 다른 키를 돌려준다. 임포트가 폴더를 연달아
  만드는 동작이 이 성질에 의존한다. `nextSort`가 React state를 읽게 바꾸면 같은 정렬 키가 여러 개 생긴다.
- **`folder.rs`의 `read()` 끝에 있는 사본 정렬을 지우지 말 것.** 폴더 백엔드(`remote/file.ts`)는 사본의
  이름과 해시를 **이 순서대로** 이어 붙여 "폴더가 그대로인가"를 판단하는 캐시 키로 쓴다. 디렉터리 순서는
  보장되지 않으므로, 정렬이 없으면 바뀌지 않은 폴더도 폴링마다 캐시를 놓치고 병합에 새 객체를 건넨다.
  그러면 위의 유휴 리렌더 함정이 되살아난다.
- **셸 명령은 `async`로 둔다.** `async`가 아닌 Tauri 명령은 메인 스레드에서 실행된다. 거기서 스레드를 막는
  대화상자(`blocking_pick_folder`, `blocking_show`)를 띄우면, 대화상자가 자신이 막은 이벤트 루프를
  기다리게 된다 ([native.md](./native.md) 「명령」).
- **셸과 웹 사이의 계약은 문자열이다.** 명령 이름, 인자 이름, JSON 필드 이름을 Rust(`lib.rs`)와
  TypeScript(`remote/file.ts`, `shared/api/native.ts`)가 따로 적는다. 한쪽만 고치면 양쪽 모두 컴파일은 되지만
  실행할 때 깨진다. 이 계약을 확인하는 것은 Linux 스모크 테스트뿐이다.
- **레퍼런스 서버의 "직접 실행했나" 검사는 실제 경로로 비교한다**(`outliner-server.mjs`의
  `runAsProgram`). `import.meta.url`을 `` `file://${process.argv[1]}` ``과 문자열로 비교하면, 경로에 공백·한글이
  있을 때(퍼센트 인코딩), Windows일 때(드라이브 문자와 `/`), 심볼릭 링크를 지날 때(macOS의 `/tmp`)
  어긋난다. 어긋나면 서버는 어떤 포트에서도 수신 대기하지 않고 **종료 코드 0으로** 끝난다 (전적 있음, 2026-09-30).
- **항목 링크의 문법 `[\w-]{1,64}`는 두 곳에 있다.** 렌더에는 `inline.tsx`의 `PATTERN`을, 백링크와
  링크 찾기에는 `links.ts`의 `ITEM_LINK`를 쓴다. 태그와 달리 하나로 합쳐져 있지 않고, 두 패턴의 뜻도 조금 다르다.
  `ITEM_LINK`는 토큰 우선순위를 모르므로 코드 스팬 안의 `((id))`도 링크로 센다. id 문법을 바꿀 때는
  두 곳을 함께 고친다.

## 실패한 대안

- **Yjs/Lexical/Firebase 기반 9,200줄 산출물 폐기** (커밋 `736c29c`에서 재작성): 범용
  에디터·CRDT 스택 위에서는 한글 IME와 병합 동작을 통제할 수 없었다. 재작성한 뒤에는 ~5,200줄이 되었고,
  의존성은 react/react-dom뿐이다.
- **인박스를 제목으로 추측하기**: 폐기. 새 워크스페이스의 첫 문서는 제목이 이미 "Inbox"이고
  `inbox: true`가 붙어 나오므로, 새 사용자는 인박스가 새로 생기는 것을 보지 않는다. v6에서 올라온
  워크스페이스에서만 첫 캡처 때 「인박스」 문서가 새로 생기는 것을 보게 된다. 제목이 "Inbox"인 문서에 표시를 붙이는 안은
  사용자 대신 문서를 고르는 일이고 제목은 바뀔 수 있으므로 버렸다.
- **서버에서 병합 판정**: 제안됐으나 폐기했다. 근거는 [ADR-0002](../adr/0002-client-side-merge.md)에 있다.
  서버에서 병합하면 GitHub 백엔드도 쓸 수 없고 E2EE도 할 수 없다.
- **contenteditable / 에디터 프레임워크**: 한글 IME가 조합하는 도중에 상태를 되돌리는 코드가
  필요해진다. 대신 행마다 둔 textarea가 브라우저 기본 동작을 그대로 쓴다.
- **동시 삽입 시 sort 키 충돌** (커밋 `669e03d`에서 수정): 두 기기가 같은 자리에 삽입하면 키가
  충돌해서 해당 행을 영구히 편집할 수 없게 됐다. 같은 감사에서 되살아난 문서가 묘비 때문에 다시 지워지는 문제,
  논리 시계 포화, 악성 페이로드를 병합할 때의 크래시, undo가 sync에 의해 되돌려지는 문제도 수정했다.
  `validate.ts`(신뢰 경계)와 `entities/outline/model/history.ts`(재스탬프 undo)가 이때 신설됐다.
