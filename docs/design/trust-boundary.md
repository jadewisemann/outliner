# 신뢰 경계와 실패 처리

> SSOT 코드: `src/entities/outline/model/validate.ts`(검증), `index.html`(CSP: **정책 값은 코드가 정본**),
> `src/app/ui/ErrorBoundary.tsx`, `src/entities/outline/api/persist.ts`, `api/github-oauth.ts`

## 외부 데이터 검증 — 던지지 말고 버리기

바깥에서 오는 데이터(동기화 응답, 가져오기 파일, 저장소에 남아 있던 값)는 전부 `validate.ts`를
통과한다 (DESIGN.md 원칙 6). 손상된 항목만 버리고 나머지는 그대로 유지한다. 그래서 적대적이거나
고장 난 서버가 문서를 지우거나 앱을 중단시킬 수 없다.

아주 먼 미래를 가리키는 타임스탬프는 현재 시각으로 바꾼다. 그대로 받아들이면 이 기기의 논리 시계가
포화되어, 이후의 모든 편집이 병합에서 지게 되기 때문이다.

이 기기에 남아 있던 값도 바깥 데이터에 해당한다. 셸이 보관하는 로컬 사본(`workspace.json`)에 `workspace`가
객체로 들어 있지 않으면 사본이 없는 것으로 본다. 그런 파일을 더 최근의 사본으로 간주하면 `migrate`가 빈
워크스페이스를 만들고, 다음에 저장할 때 그 빈 워크스페이스로 IndexedDB를 덮어쓰게 된다(2026-09-30에
수정했다). `localStorage`에 저장된 테마 값은 `light`·`dark`만 받아들인다.

## 네이티브 셸의 명령

셸이 제공하는 명령은 페이지에서 실행되는 어떤 스크립트든 호출할 수 있다. 그래서 명령 자체에 경계를 둔다.
폴더 명령은 셸이 허용한 폴더에만 접근하고(허용은 셸의 대화상자를 통해서만 이루어진다), 외부 링크를 여는
명령은 `http`·`https`·`mailto`만 받아들인다. 줄바꿈이나 NUL이 들어 있는 폴더 이름은 목록을 확인하기 전에 거절한다.
허용 목록은 한 줄에 폴더 하나를 적는 형식이어서, 그런 이름 하나로 확인을 한 번만 받고도 폴더 두 개를
허용받을 수 있었기 때문이다. 셸에서 돌려받은 파일 내용도 원격에서 받은 데이터와 똑같이 `validate.ts`를
통과한다. 자세한 내용은 [native.md](./native.md) 「폴더 허용 목록」 절에 있다.

## CSP

동기화 토큰이 `localStorage`에 저장되어 있으므로 `index.html`에 CSP 메타 태그를 둔다. 정책의 기본
구성은 `default-src 'none'` + `script-src 'self'`이다. 즉, 이 출처에서 온 것이 아니면 아무것도
실행되지 않는다. 정책을 완화한 곳은 `style-src-attr 'unsafe-inline'` 하나이며, 이것은 앱이 스스로 필요해서
연 것이다(행 들여쓰기와 가상화 패딩을 style 속성으로 지정하기 때문이다). `connect-src`는 연결할 주소를
사용자가 정하는 구조여서 좁힐 방법이 실제로 없다. `worker-src 'self'`(service worker), `img-src 'self' blob:`(첨부 object URL),
`font-src 'self'`(KaTeX 글꼴)는 각 기능이 요구한 최소한의 범위만 연 것이다. 정확한 값은
`index.html`이 정본이다. `frame-ancestors`는 메타 태그에서는 무시되므로, 헤더를 보낼 수 있는
호스트라면 헤더에 넣어야 한다.

정책은 빌드 결과물에서만 효력이 있다(dev 서버는 자체 클라이언트 코드를 인라인으로 삽입하기
때문이다). 그래서 `vite preview`를 대상으로 실행되는 `e2e/csp.spec.ts`가 "정책이 앱을 깨지 않는다 + 주입된 인라인
스크립트는 실제로 안 돈다"를 고정한다.

## 인증 = 열쇠 모델

도메인은 공개되어 있다. 하지만 서빙되는 것은 코드뿐이고, 데이터는 각 기기의 IndexedDB와 사용자가
지정한 백엔드에만 있다. PAT/OAuth 토큰을 소지하는 것이 곧 인증이고, 인증 여부는 백엔드(GitHub)가
요청마다 판정한다. E2EE 암호도 같은 경계 안에 있다. 즉, 토큰과 나란히 `localStorage`에 저장된다.
따라서 E2EE가 막아 주는 것은 "저장소를 가진 쪽이 읽는 것"이지 "이 브라우저 프로필을 가진 사람"이 아니다.

OAuth에서 서버가 맡는 부분은 function 하나(`api/github-oauth.ts`)뿐이다. 이 function은 client
secret을 브라우저로 보낼 수 없다는 단 하나의 이유 때문에 존재한다 (원칙 1). 환경 변수가 없으면 이
function은 404를 돌려주고, 로그인 버튼은 숨겨진다. 그래도 PAT 경로는 항상 동작한다.

## service worker는 셸만 만진다

`public/sw.js`는 **이 출처의 GET만** 캐시한다. 동기화 요청은 네트워크에 도달하거나,
그러지 못하면 숨김없이 실패해야 한다. 캐시된 옛 응답이 "원격의 현재 상태"로 읽혀 병합되면 안 되기
때문이다. 네비게이션 요청은 네트워크를 우선하고(그래서 새 배포가 다음 실행 때 반영된다), 이름에 해시가
붙은 자산은 캐시를 우선한다. service worker 등록은 빌드 결과물에서만 한다. 휴대폰 공유 시트를 통한
캡처(Web Share Target)는 서버가 없으므로 GET 방식을 쓴다.

## 실패 처리

- 렌더링이 실패해도 사용자가 아무것도 할 수 없는 상태에 빠지지 않도록, 오류 경계가 **백업 내려받기**를 제공한다.
- 로컬 저장이 실패하면 조용히 넘어가지 않고 상단에 배너로 알린다.
- **저장 등급이 best-effort면 그것도 알린다** (DESIGN.md 원칙 18). 앱을 켤 때마다
  `navigator.storage.persist()`를 호출하고, 등급은 동기화 패널에 항상 표시되어 있다. 배너는 다음 세
  가지가 동시에 참일 때만 뜬다: 영속 저장 요청이 거절되었고, 사본이 원격에 없고(`sync.status === "off"`), 잃을
  내용이 있다(`hasContent`). 이 세 가지가 실제로 데이터를 잃는 조건이고, 세 가지가 동시에 참이 아닐 때
  뜨는 배너는 소음이다. 예를 들어 아무것도 쓰지 않은 첫 방문자에게는 있지도 않은 내용을 잃을 수 있다고
  경고하는 셈이 된다.
- 읽을 수 없는 원격(`locked`)은 실패와 구분해서 다루고, 푸시를 멈춘다. 자세한 내용은
  [sync.md](./sync.md#종단-간-암호화-선택)에 있다.
- **묘비 파일을 읽지 못하면 빈 것으로 간주하지 않고 pull을 실패시킨다.** contents API는 1MB를 넘는
  파일에 대해서는 바이트를 돌려주지 않고 `encoding: "none"`으로 응답한다. 이 응답을 "지워진 문서가 없다"로
  해석하면 묘비 파일이 막으려는 일이 그대로 일어난다: 묘비 없이 사라진 문서는 병합에서 살아 있는 문서로
  취급되므로 이 기기가 가진 사본을 다시 올리고, 뒤이은 푸시가 자신이 아는 짧은 목록으로 실제 묘비를 덮어쓴다.
  pull을 실패시키면 둘 다 멈춘다. 동기화 루프는 백오프하면서 상태를 알리고, 실패한 pull 뒤에는 푸시가
  이어지지 않는다. 이 처리는 검증하지 못한 바깥 데이터를 그럴듯한 기본값으로 바꾸지 않는다는 이 절의
  원칙과 같은 계열이다.
